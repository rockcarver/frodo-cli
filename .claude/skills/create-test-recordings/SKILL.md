# Create test recordings

**Only run when a maintainer asks. If you are a coding agent without the needed access, stop and say so in the issue or pull request.** Recording talks to a real tenant with a maintainer's saved connection profile. Replaying does not, and anyone may do that.

The authoritative text is [test/e2e/README.md](../../../test/e2e/README.md) (how this repository uses recordings) and frodo-lib's [record and replay developer guide](https://github.com/rockcarver/frodo-lib/blob/main/RECORD_REPLAY.md) (the mechanism, every `FRODO_MOCK*` variable). This skill is the order to do things in and what to check. Test rules: [.github/instructions/tests.instructions.md](../../../.github/instructions/tests.instructions.md).

## What a recording is

Every e2e test runs `frodo` as a subprocess. frodo-lib records its HTTP traffic with Polly.js and replays it from HAR files committed under `test/e2e/mocks/`:

```
test/e2e/mocks/<group>_<hash>/<verb>_<hash>/<label or args id>/<area>/recording.har
```

Directory names are `<slug>_<hash>`, generated by Polly. **Never hand-write or rename them.** `FRODO_MOCK` selects the mode: `1` replay (no network, no credentials; what `npm test` uses), `record` records against the real network, unset means no mocking. Login traffic is shared per deployment type (`cloud`, `forgeops`, `classic`) in a shared cassette that an ordinary recording pass does not touch.

## Replay (anyone, no access needed)

```console
npx tsdown                                          # the tests run dist/, rebuild after src/ changes
npm run test:only -- test/e2e/journey-list          # one file; a Jest path pattern, not a glob
npm test                                            # everything
```

A miss fails with `Recording for the following request is not found`. An expired recording only warns (see Freshness).

## Before you record: stop unless all of these hold

- A maintainer asked for it, and you have a **working saved connection profile for a development tenant** of the right deployment type (`frodo conn list`). Recording uses `FRODO_CONNECTION` (your profile) and leaves the credential variables unset; nothing from the committed test fixtures is used to log in.
- The tenant holds **no data you cannot publish**. Recordings are committed to a public repository and secret filtering is a denylist.
- `frodo` is built from this checkout (`npx tsdown`), and, if your change depends on library changes, a linked local frodo-lib is built (see the `build-the-cli` skill).
- **The bare `frodo` in the commands below is this checkout's build, not an older install.** The npm scripts pin it for you; for a command you type yourself, run `export PATH="$PWD/test/e2e/shims:$PATH"` first (the shim runs `dist/launch.cjs`) and check with `frodo -v` that the `cli:` time is your build's. A `frodo` installed elsewhere records the wrong traffic.

No profile, no access, or any doubt: stop and tell the maintainer what is missing.

## Record one new test case

1. **Pick a label** for the case (`noDeps`, `allSeparate`, `invalidCredentials`), unique within the test file. A repeated label silently overwrites the other case's recording.
2. **Check it is not recorded yet:** `FRODO_MOCK=1 FRODO_TEST_NAME=<label> frodo <command>`. For a new label this fails; that is expected.
3. **Record it:**
   ```console
   FRODO_MOCK=record FRODO_NO_CACHE=1 FRODO_HOST=<your tenant's AM URL> FRODO_TEST_NAME=<label> frodo <command>
   ```
   `FRODO_NO_CACHE=1` is always needed: otherwise a cached token can mean the login calls never happen. **Wait for Polly's shutdown countdown** (`Polly instance '...' stopping in 3s...`, about 15 s after the last request) before you run anything else; the files are written when it ends. A command that exits with an error may record nothing.
4. **Validate** by repeating step 2: it must now replay with no network.
5. **Write the test** with exactly the command you recorded, passing the same label:
   ```js
   const { stdout } = await exec(CMD, { env: { ...env.env, FRODO_TEST_NAME: 'noDeps' } });
   ```
   Import `exec` from `./utils/TestUtils` (never `promisify(cp.exec)`: its small buffer breaks big outputs), and take the environment from `getEnv(connection)` with a connection from `test/e2e/utils/TestConfig.js`.
6. **Write the snapshot from the replay:** `npm run test:only -- test/e2e/<name>` writes the new snapshot (existing ones are untouched). Read it, then commit the test, the snapshot and the new files under `test/e2e/mocks/`.

Rules that keep recordings valid:

- **Do not put the host on the command line.** A recording's identity includes every positional word before the first flag; the host comes from `FRODO_HOST`, which `getEnv()` sets. Commands whose argument is a host (`frodo info <url>`, `frodo conn save <url>`) are the exception.
- **The command you run is the command you record.** Keep the test's `CMD` identical to the recorded one, or the test can pass without exercising the recorded traffic.
- **Set `FRODO_TEST_NAME` on every new test.** Without it the identity comes from the argument count and flag names, so two cases with the same flags collide and a renamed flag orphans the recording.

## Re-record existing tests

```console
FRODO_MOCK=record FRODO_NO_CACHE=1 npm run test:update -- test/e2e/conn-describe   # one file
FRODO_MOCK=record FRODO_NO_CACHE=1 npm run test:update -- test/e2e/conn-            # every file starting with conn-
npm run test:only -- test/e2e/conn-describe                                        # prove it replays offline
```

`test:update` re-records the test's own traffic and updates its snapshots in the same pass. A tenant that is not one of the frodo development hosts must be listed, or its traffic lands in a stray `default_*` directory instead of the per-area ones: add `FRODO_MOCK_HOSTS=<origin of your tenant>` (origins only, no `/am`, comma separated; it **replaces** the default list). If a `default_*` directory appears under `test/e2e/mocks/`, delete it and record again with the host listed.

- **Shared login recordings** change only on purpose: one pass with `FRODO_MOCK_REFRESH_SHARED_AUTH=1` (for a new realm, a scope change or expired entries), from **one** tenant only. The shared cassette is order-indexed and shared by every test of its type; mixing tenants breaks unrelated tests. Tests of invalid credentials set `FRODO_MOCK_DEDICATED_AUTH=1` and keep their own login recording.
- **Destructive tests** (import then delete) use `beforeAll`/`afterAll` guarded by recording mode and are recorded one file at a time; see "Multi-phase recording" in the e2e README. The bulk tool skips them.
- **Bulk recording** (`npm run test:record:cloud -- --dry-run --pattern <substring>` lists what it would touch; without `--dry-run` it re-records every cloud test, serially) is for changes that reshape many recordings at once, such as a change to the recording logic in frodo-lib. Use `--dry-run` first. For an everyday change re-record the individual tests.

## Review before you commit

- **Read the recording diff** (`git diff test/e2e/mocks`) for anything that should not be public: tokens, keys, e-mail addresses, tenant data. Secrets are masked by a denylist in frodo-lib (`filterRecording`), which does not know about fields it has not been taught.
- `git status` must show only the recordings, test and snapshot you meant to change. No `default_*` directory; no recording for a setup helper (recording-only setup traffic is recorded under a script-derived name and must be deleted).
- **Do not run Prettier over `test/e2e/`.** Replay matches recorded request bodies byte for byte.
- **Snapshots:** an updated snapshot must be an expected output change. Read each snapshot diff and say in the pull request what changed and why. Never update snapshots to turn CI green.

## Freshness and clean-up

- Recordings expire after 90 days. An expired recording **warns** on replay (it never fails by default); treat the warning as a prompt to re-record. `FRODO_MOCK_EXPIRES_IN` (for example `30d`) and `FRODO_MOCK_EXPIRY_STRATEGY` (`record`, `warn`, `error`) change that for one run.
- Recordings are never pruned automatically. Renaming a test or changing a command's flags leaves orphans. "Finding orphaned recordings" in the e2e README has the procedure; delete orphans in their own commit.
- The master key is never committed or generated. Suites that need one gate on `checkMasterKeyUsable()` in `test/e2e/utils/MasterKeyGate.js` and skip without a usable key (see the master-key note in the e2e README).
